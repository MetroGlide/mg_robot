# 用語集

自己位置監視 (`localization_supervisor`) の文書と設定に出てくる用語の意味と、用語どうしの関係。
仕組みの詳細は [design.md](./design.md)、設定の書き方は [parameters.md](./parameters.md)、プラグインの約束は [plugins.md](./plugins.md)。

## 呼び方とコードの名前

文書の日本語の呼び方と、コード・設定・イベントの英語の名前の対応。

| 呼び方 | コードの名前 | 意味 |
| :--- | :--- | :--- |
| 自己位置監視 | `localization_supervisor`、`Supervisor` | 自己位置を監視し、異常の判定・復旧・減速を指示する |
| AMCL 検証ゲート | `MotionGate`、設定の `gate`、`use_gate` | AMCL の姿勢を地図照合で確かめ、EKF に入れるか、止めるか、姿勢を補正するかを決める ([motion_gate.md](./motion_gate.md)) |
| 遮断条件 | `closers` | AMCL 検証ゲートを閉じるきっかけになる判定 |
| 地図照合 | `map_match` | スキャンと地図を重ねて、候補の姿勢から 1 つに決める |
| 推測航法姿勢 | `continuation` | 検証済み姿勢を、オドメトリで今に進めたもの |
| 検証済み姿勢 | `pose_confirmed`、アンカー (`_anchor`) | 地図照合で正しいと確かめた最新の姿勢 |
| 姿勢補正 | `pose_reset`、`correction` | 推定器の姿勢を、地図照合で決めた姿勢に直す |
| 除外 | `isolate` | 疑わしい情報源を、融合や候補から外す |
| 検証要求 | `request_verify`、`VerifyLocalization` | 走行側から、地図照合を 1 回求める |
| 初期全周探索 | `initial_search` | 起動の直後に、GNSS の周りを向きの全周で探す |
| 拡大探索 | `wide_search` | 決まらないときに、推測航法姿勢の周りを全周で探す |
| GNSS の再採用待機 | `gnss_probation_*`、`gnss_hold_after_distrust` | 申告の精度が急に良くなった GNSS や、除外を解いた GNSS を、しばらく、または検証済み姿勢と合うまで使わない |
| 停止要求 | `hold`、`hold_requested` | 走行を止めてほしいという要求 |
| スキャン途絶 | `gate_scan_stale`、`max_scan_age_sec` | 最新のスキャンが古く、地図照合をしない間 |
| センサ構成 | `sensor_sets` | LiDAR なしなど、欠けたセンサに応じた構成 |
| 出力部 | `actuators` | 外部のノードに指示を出す部品 |
| 走行制約 | `conduct` | 自己位置状況と危険度から、減速するかを決める |
| 自己位置状況 | `situation` | 未初期化 (`uninitialized`)・疑義 (`suspect`)・判定保留 (`undecided`)・未観測 (`unobserved`)・復旧中 (`recovering`) |
| 危険度 | `degree` | 誤差見込み ÷ 余裕距離 |
| 誤差見込み | `possible_error_m` | 最後に検証してからの、誤差の見込み |
| 余裕距離 | `clearance_m` | footprint から計画用地図の障害物までの距離 |

## 全体の流れ

1 周期 (`period_sec`) ごとに、次の順に進む。

```
情報源の標本 ─► 判定 ─► 総合 ─► 状態遷移 ─► 出力部
 (AMCL・GNSS・   (比べる)  (累積して     (除外する・   (ゲート・一時停止・
  EKF・動き・             疑う情報源   再初期化する)  倍率の配信など)
  地図とスキャン)          を決める)
```

## 入力と判定

| 用語 | 意味 |
| :--- | :--- |
| 情報源 (source) | 自己位置の材料。種類は 3 つ。`pose` は地図座標の姿勢と共分散 (AMCL、GNSS、EKF)、`motion` は相対的な動き (オドメトリ)、`reference` は照合の基準 (地図とスキャン、計画用地図) |
| 独立の情報源 | ほかの情報源に依存せずに姿勢が求まるもの (AMCL、GNSS、オドメトリ)。疑わしい情報源 (blame) の特定には、これだけを使う |
| 融合の結果 | ほかの情報源を融合して作った情報源 (EKF)。設定の `derived_from` で元の情報源を宣言する。blame には数えず、「出力が汚れているか」(contaminated) の判定にだけ使う |
| 標本 | ある時刻の、情報源の値。時刻の付いた履歴として持ち、比べるときに、動き (`motion`) で共通の時刻に移す。移せない標本は「判定できない」になる |
| 判定 (detector) | 情報源を比べて、正常かどうかを調べる検査の種類。例は `pose_consistency` (2 つの姿勢の食い違い)、`pose_jump` (姿勢の飛び)、`scan_map` (スキャンと地図の一致)、`submap_map` (局所地図と地図の一致)、`covariance` (自己申告の共分散) |
| 判定のインスタンス | 判定の種類に、情報源と引数を与えたもの。同じ種類を別の名前で何度でも作れる。例は `amcl_gnss`、`scan_ekf`、`submap_amcl` |
| Evidence | 判定のインスタンスの 1 周期の結果。「正常」「異常」「判定できない (`unknown`)」のいずれかと、`score` (1 が境目。大きいほど異常)、記録用の値を持つ |
| 判定できない | 必要な標本がない、古い、走行距離が足りないなどで、正常とも異常とも言えない周期。累積は変わらない。判定の状態としての `unknown` は、blame の `unknown` (疑わしい情報源を判定保留) とは別の意味 |
| 信頼できる周期 (trusted) | 状態が `NORMAL` で、猶予の間でなく、異常な判定がなく、`trust.require_normal` の判定が正常な周期。アンカーと残差の標本は、この周期にだけ残す |

## 総合と切り分け

| 用語 | 意味 |
| :--- | :--- |
| 総合 (fusion) | 判定のインスタンスの結果をまとめて、疑義・異常の確認・疑わしい情報源を決める方式。標準は `cusum` (強さの累積) と `consecutive` (判定が N 回続けて異常なら) |
| 累積 (cusum) | 判定のインスタンスごとに、`score` が `allowance` を超えた分をためる。`decay` で減り、`weight` で効きが変わる。一度の大きな異常も、小さな異常の積み重ねも、同じ仕組みで扱える |
| 総合の強さ (level) | 全判定の累積の合計。`suspect_level` 以上で「疑義」、`confirm_level` 以上で「異常の確認」 |
| blame | 疑わしい情報源。独立の情報源のうち、ほかと共有しない疑義が `blame_margin` 以上多いものになる。決められなければ `unknown`。2 つの情報源を比べる判定 (`amcl_gnss` など) は、両方に同じだけ疑義をかけるので、それだけでは決まらない |
| 疑義の最大値 (peak) | 疑義が始まってからの、判定のインスタンスごとの累積の最大値。blame の集計に使う。一度だけの強い証拠も、時間が経って薄まらない |
| contaminated | 融合の結果 (EKF) が、疑わしい情報源に引きずられて汚れている状態。比べた相手の独立の情報源が blame なら、その食い違いは相手のせいとして、融合の結果を疑わない |
| vouch | 「この判定が正常なあいだは、この情報源は正しい」という宣言。設定の判定のインスタンスに `vouch: [情報源]` と書く。vouch された情報源は、2 つを比べる判定の疑義から外れ、疑義はもう一方だけにかかる。判定できない周期が `vouch_hold_ticks` を超えるか、判定が異常になると外れる。その判定自身 (1 つの情報源だけを疑う判定) の異常は、vouch に関わらずその情報源を疑う |
| 猶予 (grace) | 総合を止めて、累積を進めない時間。起動直後、復旧直後、外からの再初期化の後、地図の切り替えの後に置く |

## 状態と対処

| 用語 | 意味 |
| :--- | :--- |
| 状態 | `NORMAL` (正常)、`SUSPECT` (疑義)、`ISOLATED` (除外中)、`RECOVERING` (再初期化と収束の確認中)、`DEGRADED` (復旧できない。一定の間隔で再試行しながら通知)。`recovery_enabled: false` なら、確認したら `DEGRADED` で通知するだけ |
| 除外 (isolate) | blame の情報源を使わないようにする。AMCL ならゲートで EKF への出力を止める。GNSS なら分散の倍率を上限にして、ほぼ使わない |
| `isolate_only` | その blame のときは、除外するだけにする設定。止めず (`hold_requested` を出さず)、再初期化もせず、異常がなくなれば戻る。別の情報源が blame として確認されたときだけ、通常の対処に移る。blame が `unknown` に戻っただけでは移らない。決めきれずに止めた後でも、再初期化の前に blame が分かれば、除外するだけに絞る |
| `hold_requested` | 走行を止めてほしいという要求。除外してから戻すまで出る (`isolate_only` の blame と `request_hold: false` を除く)。出力部 `pause_request` が、シーケンサへの一時停止に変換する |
| 再初期化 (reinit) | 選んだ候補の姿勢で、推定器 (AMCL と EKF) を初期化し直す。送り先は設定の `resetters` |
| 収束の確認 (convergence) | 再初期化の後に、`recovery.convergence` の判定がすべて正常な周期が続くこと。続けば元に戻す (`restore`) |
| 指示 (Directive) | 状態遷移が対処に出す指示。`isolate` (除外する)、`reinit` (候補の姿勢で初期化し直す)、`restore` (戻す) |
| 出力部 (actuator) | 状態に応じて外に働きかける部品。`gate` (AMCL のゲートの開閉)、`pause_request` (停止要求)、`clear_costmap` (コストマップを消す)、`variance_scale` (分散の倍率の配信) |
| プロファイル | 設定に重ねるまとまり。判定の有効・無効、重み、しきい値、復旧の構成を切り替える。走行中にサービス `set_profile` で切り替えられる |
| 外からの再初期化 | 自己位置監視以外が `/initialpose` などを出したこと (人による上書き)。復旧をやめて `NORMAL` に戻し、累積・アンカーを捨てて猶予を置く |

## 復旧

| 用語 | 意味 |
| :--- | :--- |
| アンカー | 信頼できた周期の、主の姿勢 (EKF) と動き (オドメトリ) の記録。疑義が始まる前の最も新しいアンカーに、その後の動きを足して、今の位置の推測 (推測航法) を作る |
| 候補 (Candidate) | 再初期化に使う姿勢の案。姿勢、共分散、由来 (`origin`)、評価を持つ |
| 候補を作るもの (generator) | `pose_source` (ある情報源の今の姿勢。GNSS が精度よく続いたときなど)、`anchor_motion` (アンカーからの推測航法)、`submap_match` (直近のスキャンをまとめた局所地図を、周りの範囲で地図に照合) |
| 評価するもの (scorer) | 候補を 0〜1 で評価する。`scan_match` (スキャンの一致)、`source_agreement` (ある情報源との近さ)、`anchor_agreement` (推測航法との近さ)、`footprint_free` (計画用地図の致死セルにかからないか) |
| 捨てる (veto) | 評価が `veto_below` を下回った候補は選ばない (例: footprint が障害物にかかる姿勢) |
| あいまい (ambiguous) | 最良の候補と、それから一定以上離れた次点の評価の差が `ambiguity_margin` 未満。判定保留ので再初期化しない |
| 局所地図 | 直近の一定の走行距離の間引いたスキャンを、動きで 1 枚にまとめたもの。1 枚のスキャンより広い範囲を見るので、似た場所の取り違えに強い |
| 照合 (matcher) | 点群を地図に合わせて、位置のずれを求める部品。標準は総当たりの `correlative` |

## 倍率と安全の信号

| 用語 | 意味 |
| :--- | :--- |
| 残差 (residuals) | 信頼できる周期の、設定で指定した 2 つの姿勢の情報源 a、b の位置の差。a が出した分散より、実際の誤差が大きいかを調べる |
| 倍率 (scale) | 残差から求める、残差の a の分散にかける係数 (1 以上、上限あり)。出力部 `variance_scale` が配信し、受け取る側が分散にかける。a の情報源を除外しているあいだは上限になる |
| 割り戻し | 受け取る側が倍率をかけて配信した標本の分散を、かけられていた倍率で割って、元に戻してから判定・候補・残差に使うこと。倍率で基準が緩んで、ずれを見逃すのを防ぐ。割り戻すのは、受け取る側に実際に届いた倍率だけ。出力部 `variance_scale` が設定にない、または無効なら届かないので、割り戻さない |
| 安全の信号 | 自己位置の判定とは別に、主の姿勢の footprint が計画用地図の致死セルにかかっているか (`footprint_in_lethal`) と食い込みの深さ (`lethal_depth_m`) を出す。走行側の BT が、領域からの脱出に使う |
| 計画用地図 | グローバルコストマップの静的な層と同じ地図。進入禁止の領域などを含む。AMCL が使う地図とは別 |

## AMCL 検証ゲート

| 用語 | 意味 |
| :--- | :--- |
| AMCL 検証ゲート | 推定器 (AMCL) の姿勢を融合 (EKF) に入れるかの切り替え。ゲートの調停ノードの 1 つの要求元として開閉する ([motion_gate.md](./motion_gate.md)) |
| 遮断条件 | AMCL 検証ゲートを閉じるきっかけを出す判定 (`Detector`)。「何か変だ」を出すだけで、正しい姿勢は決めない |
| 動きの合意 | 推定器の動きを、動きの情報源 (オドメトリ) と比べること。合わないことは分かるが、どちらが正しいかは分からない |
| 正しい直り | 推定器が、それまでの誤りから正しい姿勢へ動くこと (起動の直後の収束など)。動きの合意からは飛びと同じに見える |
| 検証済み姿勢 | 地図照合で最後に検証済み姿勢と、その時刻の動き。照合で決まったとき、一定の距離ごとの確かめで合ったとき、手動の初期姿勢を受けたときに更新する |
| 推測航法姿勢 | 検証済み姿勢を、動きの情報源で今に進めた姿勢。照合の候補の 1 つ |
| 照合で決める | 候補を地図と照合し、地図に最もよく合う仮説に決めること。次点との差が足りなければ決めずに待つ |
| 手動の初期姿勢 | 専用のトピックで人が与える姿勢。検証済み姿勢として扱う。専用のトピックを通らない `/initialpose` は、推定器の振る舞いとして判定を受ける |

## 評価

| 用語 | 意味 |
| :--- | :--- |
| オフライン評価 | rosbag などの記録した標本から `Snapshot` を作り、実時間を待たずに自己位置監視を回す評価。記録済みの推定器の出力を使うので、再初期化した後の挙動は見られない |
| 故障注入 | 記録した標本を書き換えて、正解の付いた故障 (AMCL を飛ばす・少しずつずらす、GNSS にずれを足すなど) を作ること。検知までの時間、誤検知、blame の正しさを測る |
| 誤検知 | 故障がないのに、疑義・異常の確認・再初期化をしたこと |

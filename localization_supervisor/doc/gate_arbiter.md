# gate_arbiter_node (ゲートの調停)

複数の要求元が、同じゲート (`std_srvs/SetBool` で開閉するサービス。例: 推定器の出力を融合に入れるかの中継) を直接切り替えると、互いの意図を上書きする。
そこで要求元ごとのサービスを設け、**すべての要求元が「開ける」のときだけ**ゲートを開く。ゲートを操作するのは、このノードだけにする。

調停の規則は `core/gate_arbiter.py` (ROS に依存しない)、ノードは `ros/gate_arbiter_node.py`。

## 入出力

| 種類 | 名前 | 型 | 内容 |
| :--- | :--- | :--- | :--- |
| サービス | `~/<要求元>/change_publish_state` | `std_srvs/SetBool` | 要求元ごとの開閉の要求 (data=true で開けてよい) |
| クライアント | `gate_service` | `std_srvs/SetBool` | 操作するゲート |
| 配信 | `~/state` | `localization_supervisor_msgs/GateState` | 状態 (transient_local。変化したときだけ) |

## 振る舞い

- ある要求元が閉じている間は、他の要求元が「開ける」を送っても開かない。
- 反映に失敗したり、ゲートが後から起動したりしても、`period_sec` の周期で合わせ直す。ゲートのノードが落ちて戻ったときも (再起動で開いた状態に戻るため) 送り直す。ただし、合わせ直しの周期より短い間の再起動は検出できない。
- 閉じた後に開けるのは、閉じた要求元の責任 (自動解除はしない)。
- 状態の `desired` は要求元の意図 (全員が開けてよいとき true)、`applied` はゲートへの反映済みか (ゲートのノードの再起動で不明になったときは false)、`holders` は閉じている要求元。

## 診断とイベント

- 診断 `<ノード名>: gate`: 要求がゲートに反映できていれば `OK` (閉じている要求元がいても、意図どおりなので `OK`)、反映できていないあいだは `WARN` (`not applied: ...`)。ハードウェア ID は `hardware_id`。
- イベント `gate.changed` (`requester`、`attached`、`holders`): 全体の意図か、閉じている要求元が変わったときに出す。`warn_holders` の要求元が閉じているときは WARN、それ以外は INFO。

## パラメータ

| パラメータ | 内容 |
| :--- | :--- |
| `gate_service` | 操作するゲートのサービス |
| `requesters` | 要求元の名前の一覧。要求元ごとにサービスを作る |
| `warn_holders` | この要求元が閉じたときは、異常による切り離しとして WARN で出す |
| `hardware_id` | 診断のハードウェア ID |
| `period_sec` | ゲートに合わせ直す周期 [s] |

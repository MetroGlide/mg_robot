# 設計

自己位置推定の出力を、ほかの情報源や地図と見比べて検証し、ずれたときに知らせ、復旧するフレームワークの設計。
特定の推定器やセンサを知らない。どの情報源を使い、どう比べ、どう総合するかは、すべて設定ファイル ([parameters.md](./parameters.md)) で宣言する。
プラグインの約束と追加の手順は [plugins.md](./plugins.md)。

## 層

| 層 | 場所 | 内容 |
| :--- | :--- | :--- |
| 中核 | `localization_supervisor/core/` | ROS に依存しない (標準ライブラリと numpy・scipy・yaml だけ)。標本の履歴、時刻のそろえ方、判定、総合、状態遷移、アンカー、復旧の候補と照合、設定の検証、故障注入、評価の集計 |
| ROS | `localization_supervisor/ros/` | 入力のアダプタ (メッセージ → 標本)、再初期化の送り先、対処、オフライン評価の実行部、ノード、診断、イベントの出力 |

中核が ROS に依存しないことは、`test/test_framework_independence.py` で確かめる。オフライン評価も他のロボットでの利用も、中核をそのまま使う。

## 1 周期の流れ

```
メッセージ ─► 入力のアダプタ ─► SampleStore (情報源ごとの標本の履歴)
                                      │ 周期ごとに snapshot(時刻)
                                      ▼
                                   Snapshot ─► 判定のインスタンス ─► Evidence
                                                                        │
                                       総合 (FusionStrategy) ◄──────────┘
                                         │ FusionResult (強さ・疑い・確認・blame・contaminated)
                                         ▼
                                     状態遷移 ─► 状態・行動・イベント
                                         │
                                     アンカー (信頼できる周期の姿勢と動き)
                                         │
                                     復旧の計画 (再初期化が要るあいだ。候補 → 評価 → 選ぶ) ─► 指示 (Directive)
                                         │
                                     安全の信号 (footprint が計画用地図の致死セルにかかっているか)
```

`core/supervisor.py` の `Supervisor.step(snapshot)` が、判定から安全の信号までを行い、推定器や周りへの働きかけを指示 (`Directive`: `isolate`・`reinit`・`restore`) として返す。ノードもオフライン評価も、これを呼ぶ。
指示を実行するのは ROS 側 (再初期化の送り先と対処。ノード)。中核は何も送らない。
周期の初めに、判定が使う地図が替わっていないかを見る (後述)。状態のメッセージと診断の中身は、周期の結果から `core/status.py` で作る。

## 情報源

| 種類 | 標本 | 例 |
| :--- | :--- | :--- |
| `pose` | 地図座標の姿勢と共分散 (x, y, yaw) | 粒子フィルタの推定、融合の推定器の出力、地図座標に直した GNSS |
| `motion` | ゆっくりずれる座標での姿勢 (2 つの時刻の差が動き) | ホイールオドメトリ、LiDAR オドメトリ |
| `reference` | 地図と最新のスキャン | 占有格子と LaserScan |

- 各情報源は、独立か、融合の結果 (`derived_from`) かを宣言する。融合の結果は、疑わしい情報源の特定に使わない (後述)。
- 姿勢の融合 (姿勢そのものを良くする) は推定器の役割で、このフレームワークは担わない。監督する側とされる側を同じにしないため。

## 時刻のそろえ方

標本は届く時刻がそろわない。比べるときは、動きの情報源の履歴で、各標本を共通の時刻 (周期の時刻、またはスキャンの時刻) に移す。

```
map→base(t_to) = map→base(t_from) · [odom→base(t_from)⁻¹ · odom→base(t_to)]
```

- 動きの情報源は `timeline.motion_priority` の順に試し、両方の時刻を含む最初のものを使う。
- 移した距離・回転に比例する分散を足す (`alignment_std_per_m`、`alignment_std_per_rad`)。
- 移せない標本 (履歴の範囲外) を使う判定は「判定できない」になる。判定のプラグインが個別に時刻のずれを扱うことはしない。

## 判定と Evidence

判定のインスタンスは、`Evidence` (正常 / 異常 / 判定できない、正規化した `score`、記録用の値) を返す。`score` は 1.0 が異常のしきい値に当たる。
同じ判定のクラスを、別の名前・別の情報源・別の引数で何度でも使える。標準の判定は [plugins.md](./plugins.md#標準の判定)。

同じ周期の中で使い回せる計算 (姿勢ごとのスキャンの座標変換) は `Snapshot.cached` で共有し、周期をまたいで使い回せる地図の局所の距離場は、`reference` の情報源が持つ。

スキャンを地図に照合する判定は、見ている範囲で性質が違う。

- 1 枚のスキャン (`scan_map`): 毎周期見られるが、似た場所の取り違えや、地図とセンサの見え方の違いに弱い。ほかの 1 枚のスキャンの判定は [構想](../../doc/ideas/localization_single_scan_checks.md)。
- 直近の一定距離のスキャン (`submap_map`): 動きの情報源で 1 枚の局所地図にまとめて照合する (`core/scan_buffer.py`)。広い範囲を見るので、推定器が誤った場所に自信を持って収束した状態に強い。照合は数秒おきにする。

推定器が同じスキャンと地図を使っていると、その推定器の姿勢での一致は独立な証拠にならない (誤った場所に収束していても、よく合って見えやすい)。重みは、この独立性を考えて決める。
一致率などの絶対値は、地図の質やセンサの特性で決まる。正常なとき (状態が `NORMAL` で、その判定も正常) の値の中央値を基準にする判定が多い。環境によっては、正しい姿勢と区別できない判定もあるので、オフライン評価で確かめてから有効にする。

## 総合

| 方式 | 内容 |
| :--- | :--- |
| `cusum` | インスタンスごとの漏れのある累積 `S_i = max(0, decay_i·S_i + weight_i·(min(score_i, max_score_i) − allowance_i))`。総合の強さは `Σ S_i`。大きく飛ぶ場合 (1 回の大きな score) も、少しずつずれる場合 (しきい値の前後の score の積み重ね) も同じ仕組みで扱う |
| `consecutive` | インスタンスごとに、続けて異常だった回数で判断する。インスタンスの `options` で、疑い・確認の回数と、他の判定による裏付け (`corroborate_after`) を決める |

- 判定できない周期は、累積・回数を変えない。起動直後などの猶予の間は、総合を進めない (判定の値は記録する)。
- `cusum` で重みが 0 のインスタンスは、記録のためだけに判定する (累積にも、異常の有無にも効かない)。新しい判定を、総合に影響させずに試すときに使う。
- `allowance` を 1.0 より下げると、しきい値の手前から累積する (少しずつずれる場合に早く気づく)。正常なときの score の分布 (オフライン評価で出せる) より上にする。
- 「異常がなくなった」(`cleared`) は、判定できたインスタンスがあり、どれも異常でない周期。状態遷移が、それが続くのを数える。

### 疑わしい情報源の切り分け (blame・contaminated)

- 独立の情報源だけを疑う。インスタンスの累積の、疑いが始まってからの最大値を、そのインスタンスが疑いをかける情報源 (`subjects`) に足す。
- 1 位と 2 位の差 (他と共有しない疑い) が `blame_margin` 以上なら、その情報源を `blame` とする。決めきれなければ `unknown`。
  - 2 つの情報源の食い違いだけでは、両方に同じだけ足すので決まらない。片方だけを疑う判定 (飛び、地図との一致) が加わると決まる。
  - 片方を `vouch` する判定 (設定の `vouch`) が、直近で「判定できて正常」なら、その片方は正しいと見なして、食い違いの疑いをもう一方だけに足す (両方が正しいと示されているときは、両方に足す)。たとえば、AMCL と GNSS が食い違っているとき、AMCL の姿勢でスキャンを地図に照合する判定が正常なら、GNSS を疑う。判定できない周期が `vouch_hold_ticks` を超えるか、異常になれば示すのをやめる。
  - 最大値を使うので、一度だけの強い証拠 (飛び) が時間とともに薄まらない。
- 融合の結果が関わる判定は `blame` に数えず、今の累積があれば、その情報源を `contaminated` (出力が汚れている) とする。ただし比べた相手の独立の情報源が `blame` なら、その食い違いは相手のせいとみなす。
- 融合の結果を数えないのは、融合の結果は元の情報源に引きずられるため。たとえば推定器が誤った情報源に引きずられると、その情報源とは一致し、正しい情報源と食い違うので、多数決では正しい情報源を疑ってしまう。
- ゆっくりしたずれ (ドリフト) は、2 つの独立の情報源のどちらがずれたかを、同じ種類の情報だけでは区別できない。このときは `unknown` になる。

## 状態遷移

`NORMAL` / `SUSPECT` / `ISOLATED` / `RECOVERING` / `DEGRADED` (`core/state_machine.py` の図)。

- `recovery_enabled: false`: 確認したら `DEGRADED` で知らせるだけ。異常がなくなった周期が `clear_ticks` 回続けば `NORMAL` に戻る。
- `recovery_enabled: true`: 確認したら `blame` を添えて切り離しを求め (`ISOLATED`。指示 `isolate`)、待ってから再初期化を求め (`RECOVERING`)、`recovery.convergence` のインスタンスがすべて正常な周期が続けば戻す (指示 `restore`)。収束しない・候補を選べない時間切れが続けば `DEGRADED` (一定の間隔で再び `RECOVERING` を試す)。切り離しから戻すまでは `hold_requested` (走行を止めてほしい。`request_hold: false` なら出さない)。
- `blame` が `isolate_only` の情報源のときは、切り離すだけにする。状態は `ISOLATED` のまま、`hold_requested` を出さず、再初期化も求めず、異常がなくなった周期が `clear_ticks` 回続けば `NORMAL` に戻る (指示 `restore`)。たとえば GNSS のずれは、推定器 (AMCL) が正しいと分かっているなら、再初期化せずに、GNSS の分散を上げて使わないようにするだけでよい。
  - 決めきれずに (`blame` が `unknown`) 止めた後でも、再初期化の前に `blame` が `isolate_only` の情報源と分かったら、切り離すだけに絞って、止めるのをやめる (正しいと示す判定が、後から判定できるようになった場合)。
  - 切り離している間に、別の情報源が `blame` で異常を確認したら、その `blame` の対処に移る (通常の切り離し・停止・再初期化)。`blame` が `unknown` に戻っただけでは移らない (正しいと示す判定は、停止中などで判定できない周期が続くと外れるため。その間は、切り離したまま、他の情報源で走る)。
- 再初期化の候補は、`blame` の情報源を使うもの (候補を作るもの、評価するもの) を使わない。疑わしい情報源の位置に、推定器を引き戻さないため。
- `NORMAL` に戻るとき、再初期化を求めるときは、総合の累積を捨てる。

## 復旧

状態が `RECOVERING` になると (`Action.REINIT`)、`Supervisor` は `recovery.selection.retry_sec` ごとに復旧を計画する (`core/recovery/planner.py`)。選べなければ見送って次の周期に再び試し、状態遷移の時間切れ (`recover_timeout_sec`) が来れば再試行か `DEGRADED` になる。

1. **候補を作る** (`CandidateGenerator`。設定の順): 指定した姿勢の情報源の今の姿勢 (`pose_source`。精度の良い標本が続くまで待つ)、アンカーに動きを足した姿勢 (`anchor_motion`。推測航法。動いた距離に比例して共分散を増やす)、その姿勢の周りでスキャンを地図に照合して見つけた姿勢 (`submap_match`。上位の互いに離れたものを複数)。作れなかった理由は `status` に残り、見送りのイベントに添える。
2. **評価する** (`CandidateScorer`。0〜1): 候補の姿勢でスキャンを地図に重ねた一致率 (`scan_match`)、footprint が計画用地図の致死セルにかからないか (`footprint_free`。`veto_below` で捨てる)、指定した姿勢の情報源との近さ (`source_agreement`)、推測航法の予測との近さ (`anchor_agreement`)。
3. **選ぶ**: 評価の重み付き平均で順位を付ける。次の場合は再初期化しない。
   - 最良が `min_score` に届かない (`low_score`)
   - 最良と、それから `separation_m` 以上離れた次点の差が `ambiguity_margin` 未満 (`ambiguous`。似た場所の取り違え)
   - 候補がない (`no_candidates`)、すべて捨てられた (`all_vetoed`)

   評価するものがなければ、最初に作られた候補を選ぶ (`unscored`)。
4. **指示を出す**: 選べたら `reinit` の指示 (姿勢と共分散) を出し、累積・判定の内部状態を捨てて猶予を置く。アンカーとスキャンのバッファは再試行のために残す。

照合 (`core/matcher/`) は差し替えられる。標準の `correlative` は numpy の総当たりで、粗い格子で探して、上位の互いに離れたものを細かい格子で絞り込む。探す範囲は予測の共分散から決め、上限がある。
スキャンのバッファ (`recovery.scan_buffer`) があれば、動きで直近のスキャンを 1 枚の局所地図にまとめて照合・評価する (1 枚より似た場所の取り違えに強い)。

- スキャンの照合は、廊下のように進行方向の位置が定まらない場所で、似た一致の候補が並ぶ。そのとき、GNSS との近さや推測航法の予測との近さを小さい重みで足して、並んだ候補から選ぶ。
- ロボットが運ばれた (誘拐) ときは、推測航法の予測が外れる。GNSS のような、運ばれた後の位置を示す情報源の候補が要る。そのようなものがなければ、スキャンの一致が低い候補は退けられ、復旧できずに `DEGRADED` で知らせる。
- 候補の作り方・評価の重み・選び方は、環境と地図で決まる。オフライン評価 (`apply_reset`・誤った復旧の数) で確かめてから有効にする。

### 指示を実行する側 (ROS)

| 指示 | 実行するもの |
| :--- | :--- |
| `reinit` | 再初期化の送り先 (`PoseResetter`) が、選んだ姿勢を推定器に送る。設定の順にすべてに送る |
| `isolate`・`restore`・状態 | 対処 (`Actuator`) が、周期の結果 (状態・`blame`・`hold_requested`・指示) から、ゲートの開閉・一時停止の要求・サービスの呼び出しをする |

監督が送った再初期化のメッセージ (`/initialpose` など) は、`external_reinit.topics` と同じトピックを使うことがある。送るとき、トピックとヘッダの時刻を覚えておき (`ros/own_messages.py`)、受け取ったときに照らし合わせて、外からの再初期化と取り違えない。

## アンカー

信頼できる周期 (状態が `NORMAL`、猶予の外、どの判定も異常でなく、`trust.require_normal` のインスタンスが正常) に、主の姿勢と動きの情報源の姿勢の組を残す。
残すのは時間と走行距離の上限まで。復旧では、疑いが始まった時刻より前の最も新しいアンカーに、その後の動きを足して候補を作る。

## 残差と分散の倍率

地図と GNSS のずれは、場所ごとに違う (地図は SLAM から作るため)。一定のバイアスとしては補正せず、信頼度 (分散) だけを調整する。

- 自己位置が信頼できる周期 (アンカーを残す条件と同じ) に、設定の 2 つの姿勢の情報源 a と b の位置の差の二乗 Δ² と、a の分散、b の分散 + 時刻のずれの分散を残す (`core/residuals.py`)。
- a の自己申告が正しければ、Δ² の平均は `2 × (a の分散 + 他の分散)` になる。それより大きければ、a の実際の誤差は自己申告より大きいので、a の分散にかける倍率 `S = (Δ² の平均 / 2 − 他の分散) / a の分散` を求める (1 以上、上限以下。急に変えず、`gain` の割合で近づける)。
- 受け取る側は a の分散に倍率をかけるので、届く a の標本の分散は倍率をかけた後の値になる。標本を入れるとき (`SampleStore`) に、そのとき効いていた倍率 (出してから `scale_delay_sec` 後に効く) で割って、倍率をかける前に戻してから残す。判定・復旧の候補・残差は、どれも倍率をかける前の分散を使う。倍率で緩んだ基準では、a の異常を見逃し、切り離しの間に「正常に戻った」と誤って判断してしまうため。倍率を受け取る側がいないと、倍率は上限に向かうだけで害はない。ノードが、受け取る側に実際に届く倍率を `note_scale` で記録する (対処 `variance_scale` が設定にない、またはプロファイルで無効なら、倍率は届かないので 1)。オフライン評価は、記録の標本に倍率がかかっていないので、割り戻さない。
- b が a を含む融合の結果 (例: GNSS を含む EKF) のときは、a を過大に信頼するほど残差は小さく出る。倍率は、ずれが大きい区間を見つける目安になる。
- 倍率が `notify_scale` 以上の状態になった・戻ったとき、イベント `residual_changed` を出す (地図と GNSS の位置合わせを見直すきっかけ)。
- 信頼できない周期、外からの再初期化・地図の切り替えの後は、標本と倍率を捨てる。

出力は対処 `variance_scale` が配信する。a を切り離しているあいだ (`blame` が a で、状態が `ISOLATED` 以降) は、倍率を上限にして、ほぼ使わないようにする (`StepResult.applied_scales`)。

## 安全の信号

自己位置の判定とは別に、指定した姿勢 (`safety.pose`) の footprint が、計画用地図 (`safety.map`) の占有 (致死) セルにかかっているかを求める (`core/safety.py`)。

- `fraction`: footprint の中の標本の点のうち、致死セルにある割合
- `depth_m`: 致死セルにある点から、最も近い致死でないセルまでの距離の最大 (食い込みの深さ。測る範囲に上限がある)

自己位置が正常なのに致死セルにかかっていれば、走行側で脱出する。自己位置が疑わしいときは、復旧に任せる (使う側が状態と組み合わせて決める)。
入ったとき・出たときにイベントを出す。

## 想定外への対処

- **外からの再初期化**: 人やほかのノードが推定器を初期化し直したら (`Supervisor.external_reinit`)、状態を `NORMAL` に戻し、累積・判定の内部状態 (正常なときの基準、スキャンのバッファなど)・アンカーを捨てて、猶予を置く。
- **地図の切り替え**: 判定が使う地図が替わったら、同じように捨てて猶予を置く。計画用地図のように、判定が使わない地図が替わっても捨てない。
- **走行中の変更**: プロファイル、判定の無効化、重みを変えられる (`set_profile`・`set_disabled`・`set_weight`)。無効化と重みは、プロファイルの上に重ねる。

## プロファイル

基の設定に重ねる部分の設定。判定の有効・無効 (`enabled_detectors`)、重み・しきい値、総合の方式などを、まとめて切り替える。
切り替えると、判定・総合・状態遷移・アンカーを作り直す (状態は `NORMAL` から)。プラグインの種類 (`type`) が変わる辞書は、重ねずに置き換える。

## オフライン評価

`ros/offline_runner.py` は、rosbag を入力のアダプタで読み、Snapshot を作って、実時間を待たずに `Supervisor` を回す。

- 推定器の出力は記録済みのものを使うので、再初期化した後の挙動は実際には見られない。`--apply-reset` に姿勢の情報源を並べると、再初期化の指示の後のその情報源の標本を、選んだ姿勢に合わせて、復旧して `NORMAL` に戻るまでを真似る (実際の推定器の収束は再生評価で見る)。
- `core/faults.py` で、記録した標本を書き換えて故障を注入する (姿勢のずれ・ドリフト、標本の欠落、スキャンの欠測・間引き)。融合の結果を一定の割合だけ引きずらせることもできる (`followers`)。故障を注入する前の記録は、再初期化の候補の誤差を測る真の姿勢になる (`--truth`。既定は `anchors.pose`)。
- `core/evaluation.py` で、故障の区間を正解として、確認までの時間・`blame`・判定のインスタンスごとの検知と誤検知率を出す。検知の対象は姿勢をずらす故障だけで、標本が欠けるだけの故障の区間は「異常がない」区間として誤検知を数える。再初期化は、故障ごとの指示までの時間・候補の誤差・復旧までの時間と、誤った復旧 (候補の誤差が `--ok-threshold` を超えたもの)・故障の区間の外の指示・見送りの数を出す。
- 記録したときに起きていた故障は、注入せずに正解としてだけ与える (`--labels`)。

```bash
ros2 run localization_supervisor offline_runner.py --config <設定> \
    --bag <bag>[:トピック,...] [--bag ...] --map <reference の情報源>=<map.yaml> \
    [--faults <故障の定義>] [--labels <故障の定義>] [--profile <名前>] [--apply-reset <情報源,...>] [--out <出力先>]
```

出力は `timeline.jsonl` (周期ごとの状態・総合・判定の値)、`events.jsonl`、`report.md`。

## ノード

`localization_supervisor_node` (`ros/supervisor_node.py`) は、設定ファイルの入力のアダプタで購読し、周期ごとに `Supervisor` を回して、状態・診断・イベントを出し、指示を再初期化の送り先と対処に渡す ([supervisor_node.md](./supervisor_node.md))。

# 最終形の構成 (一部未実装)

自己位置推定の監督の、目指す構成。今の実装 ([design.md](./design.md)、[motion_gate.md](./motion_gate.md)) から、門のノードを監督に統合し、状態・程度・対処の対応表・復旧の段を足した形。
特定のロボットに依存しない。ロボットごとの部品のつなぎ方と構成の切り替えは、使う側のパッケージの文書に書く (例: [mg_navigation の localization_target.md](../../mg_navigation/doc/localization_target.md))。

各節の見出しに、実装の状況を付ける。

| 印 | 意味 |
| :--- | :--- |
| (実装済み) | 今のコードにある。場所を節の中に書く |
| (一部) | 部品はあるが、最終形の形になっていない。違う所を節の中に書く |
| (未実装) | 設計は決まっていて、コードがない |
| (未確定) | 測ってから決める。選択肢と、決める測定を [未確定の項目](#未確定の項目) に書く |

数値は、どれも「例」。値は各ロボットの設定ファイルが正。

## 目的と不変条件

ずれたまま走らない・止まったままにならない・人手なしで戻る。どのシナリオにも、次の条件を当てはめる。

1. 真値から一定以上ずれた姿勢で、通常の速度のまま走る距離に上限がある。
2. 止まっている間に何もしない時間に上限がある。走行計画の失敗で止まっている間も含める。
3. 停止の合計は段ごとの上限以下。上限に達したら次の段へ進み、最後は縮退走行 (低速で、走ってよい距離に上限をつけて走る)。止まったままにしない。
4. 正常時に、誤った減速・停止・置き直しをしない。
5. 確かめずに通常の状態へ戻らない。

満たせない状況は、名前をつけた例外として持ち、例外の間だけ、指定した条件を外す ([例外](#例外-未実装))。

## 役割の分担

| 役 | 担うもの | 決めないこと |
| :--- | :--- | :--- |
| 走る | 走らせる推定器 (例: EKF などの融合)。走行に使う姿勢を出す | 正しさ |
| 気づく | 閉じる理由の部品、健全さの判定、見張り役との食い違い。「何か変だ」を出す | どの情報源が正しいか |
| 判定する | 地図との照合。候補のうち、どれが地図に合うかで決める | — |
| 対処する | 監督。門の開閉、置き直し、減速、一時停止、復旧の段 | — |
| 戻す | 構成の切り替え。今の実機の構成へ戻す道を残す (使う側のパッケージ) | — |

気づく部品は誤って気づいても、照合 1 回で元に戻る。そのため、気づく部品を足すのは安く、判定する部品 (照合) の正しさが全体の正しさを決める。

## 構成

置き直し (推定器・融合への姿勢の送り込み) と門の開閉を出すのは、監督のノード 1 つだけにする。監督のノードの中の門 (設定の `gate`、ノードの `use_gate`) で実装した ([design.md](./design.md#門を入れたとき))。門のノードは消した。

```
情報源 (推定器・GNSS・融合の結果・動き・地図とスキャン)
  │
  ▼
監督のノード ─────────────────────────────────────────────────────────────
│ 気づく:   閉じる理由の部品 (動きの合意、GNSS との食い違い)
│           健全さの判定 (今の判定と総合)、見張り役との食い違い (未確定)
│ 判定する: 地図との照合 (候補 → 仮説にまとめる → 決める)
│ 状態と程度 ─► 対応表 ─► 対処
│ 復旧の段、確かめの要求、未初期化の処理 (起動・地図の切り替え)
└──────────────────────────────────────────────────────────────────────────
  │
  ├─► 門 (ゲートの調停の要求元)        ├─► 置き直しの送り先 (推定器・融合)
  ├─► 一時停止の要求・減速の上限       ├─► 観測を増やす動作の要求
  └─► 状態 (LocalizationStatus)・診断・イベント
```

- 今の監督の中核 (標本・判定・総合・状態遷移・アンカー、[design.md](./design.md)) を土台にし、門の中核 (`core/motion_gate.py`・`core/map_match.py`) を、その部品として入れる (実装済み)。
- 入力は今の監督と門で同じ情報源の一覧なので、1 つのノードにすると購読と地図の距離場が 1 つになる。

## 情報源

今の監督と同じ (`pose`・`motion`・`reference`、[design.md](./design.md#情報源)) (実装済み)。足すもの:

- 情報源ごとの有効・無効を設定で切り替える。欠けた情報源を使う判定は「判定できない」になる (実装済み。判定できない周期は総合に数えない)。
- 観測の形の共通化: 照合・局所地図の照合・広い照合・初期化は、「視野と届く距離を持つ 2D の距離の観測」を入力にする。LiDAR のスキャンとカメラの深度から作った同じ形の観測が、同じコードを通る。結果には向きごとの拘束の強さを付ける (未実装)。

### 「確かめた」の定義 (一部)

確かめる相手と独立な絶対の情報源が、すべての向きで十分に拘束しているときだけ「確かめた」とする。

- 独立の数え方は、何に頼っているか (地図、形、GNSS、車輪、きめ) の単位で数える。推定器と照合が同じ地図とスキャンを使うなら、地図については 1 つ。
- 今は、照合の一致率と次点との差で決めていて、向きごとの拘束の強さを見ていない (一部)。

## 気づく部品

### 閉じる理由の部品 (実装済み)

[motion_gate.md](./motion_gate.md#閉じる理由の部品) の部品をそのまま使う。

- 動きの合意: 推定器の動きを、動きの情報源と比べる。1 回ごとの差と、直近の一定時間で最も古く受け入れた姿勢を今に進めたものとの差の両方で比べる。
- GNSS との食い違い: 推定器の位置が、健全な GNSS から一定以上離れたまま続く。置き直しの後の猶予の間も使う (`active_in_grace`)。
- 動きの合意は正しい直り (推定器が誤りから正しい姿勢へ動くこと) も飛びと同じに見る。そのため、閉じたら必ず照合で決め、開けるのも照合が決めたときだけにする。情報源が再び合ったことでは開けない。

### 健全さの判定 (実装済み、監督)

今の監督の判定と総合 ([design.md](./design.md#判定と-evidence)) を残す。門を統合した後も、GNSS を疑う判定と、疑った GNSS の分散を広げる対処 (`variance_scale`) は監督の役として残す。監督が GNSS を疑っている間、門は GNSS を使う閉じる理由の部品と GNSS の候補を使わない (実装済み)。

- 門は推定器だけを止める。門を閉じている間、融合は動きと GNSS だけで進むので、GNSS がずれていると融合はずれた GNSS へ寄る。疑った GNSS の分散を広げて、寄らないようにする。
- 根拠: 門だけの構成 (GNSS の扱いなし) では、GNSS が弱る異常のシナリオで、推定器は正しいのに融合がずれた GNSS に付いていった (2026-11-25 の Gazebo の計測。使う側のパッケージの [localization_target.md](../../mg_navigation/doc/localization_target.md#根拠))。

### GNSS の門 (未実装)

推定器と同じく、GNSS にも門を持てる作りにする。

- 閉じる理由の部品: GNSS の動いた量と動きの情報源の比較、申告の精度が急に良くなったときの見習い期間。
- 推定器と GNSS の門が両方閉じたときの時間の上限と、その後の減速・一時停止。
- 止める仕組み (切り替えのノードか、GNSS の分散を上げる指定か) は未確定。

### 見張り役との食い違い (未確定)

走らせる推定器と別に姿勢を出す見張り役 (例: 窓つきの因子グラフ) を置き、食い違いを不確かさで割った量を証拠として時間で溜める。要るか、走らせる推定器にするかは、記録の再生の比較で決める。構想は [doc/ideas/localization_graph_aggregator.md](../../doc/ideas/localization_graph_aggregator.md)。

- 見張り役が止まる・遅れると、食い違いは「判定できない」。走行は続き、飛びの検出は動きの合意で続く。

## 地図との照合で決める (実装済み)

規則は [motion_gate.md](./motion_gate.md#照合で決める) のとおり。要点:

- 候補は、前の続き (最後に確かめた姿勢を、動きで今に進めたもの)、推定器、融合の結果、GNSS、外から与えた初期姿勢。候補ごとに、探す範囲をその不確かさで決め、上限を置く。
- 照合した後の姿勢が近い候補を同じ仮説にまとめ、離れた仮説を見分けるのに使う。細かい位置合わせには使わない (一致率の山は近い所でほぼ平らなため)。
- 最良の仮説に推定器が入っていて、一致率が見分けられなければ、推定器をそのまま採る。
- 離れた次点との差が足りなければ、決めずに待つ。

統合の後は、今の監督の復旧の計画 ([design.md](./design.md#復旧) の候補 → 評価 → 選ぶ) の「選ぶ」を、この規則に置き換える。候補を作る部品 (`pose_source`・`anchor_motion`・`submap_match`) は、候補として残す (実装済み。門があるとき。門がない構成は今の計画のまま)。

## 状態 (一部)

| 状態 | 入る条件 |
| :--- | :--- |
| 未初期化 | 起動・地図の切り替えの直後で、確かめた姿勢がない |
| 正常 | 溜まった証拠がどれも閾値より小さい |
| 疑い | どれかの証拠が閾値を超えた (門を閉じた、食い違い、を含む) |
| 決めきれない | 照合で決まらない |
| 見えない | 独立の絶対の情報源と比べられないまま、一定の距離を走った |
| 復旧中 | 止まって段を進めている |

- 1 つ軽い状態へ戻るのは、確かめたときだけ (不変条件 5)。今の監督で、復旧を無効にした構成が「異常がなくなった周期の数」だけで正常に戻る経路 (`clear_ticks`) は、確かめてから戻す (`verify_return`) を既定にして、なくす (未実装)。
- どの情報源を疑ったかは、状態の属性 (`blame`) として出す (実装済み)。
- 今の状態 (`NORMAL`・`SUSPECT`・`ISOLATED`・`RECOVERING`・`DEGRADED`) と門の状態 ([motion_gate.md](./motion_gate.md#状態)) との対応、状態のメッセージの値の決め方は未確定。

## 程度 (未実装)

起こりうる誤差 ÷ 余裕 (ロボットの端から、計画用の地図で通れない所までの距離) の区分。軽い / 中 / 重い。

- 起こりうる誤差は、2 つのうち大きい方。
  - 不確かさ: 見張り役が動いていればその不確かさ。動いていなければ、最後に確かめてからの推測の距離に比例して増える上限。融合の共分散は使わない (推定器を棄却なしで入れていると楽観的になるため)。
  - 状態ごとの下限 (疑いより、決めきれない・見えないを大きくする)。
- 比は、横の成分 ÷ 近い側の余裕と、前後の成分 ÷ 前方の余裕の大きい方。上げるのはすぐ、下げるのは履歴をおく。
- 正常の状態では程度を使わない (正常時に減速しないため。不変条件 4)。

## 状態 × 程度 → 対処 (未実装)

対応表を設定に持ち、プロファイルで升目ごとに差し替える。対処を決める順は、対応表 → センサの組のプロファイル → 例外。後ろが上書きする。

| 状態 \ 程度 | 軽い | 中 | 重い |
| :--- | :--- | :--- | :--- |
| 正常 | 通常 | 通常 | 通常 |
| 疑い | 記録 + 照合 | 減速 + 照合 | 減速 + 照合 |
| 決めきれない | 減速 | 止める + 局所地図の照合 | 止める + 局所地図の照合 → 広い照合 |
| 見えない | 減速 | 縮退走行 | 止める + 観測を増やしてやり直す |
| 未初期化 | 走りながら照合 | 同左 + 減速 | 止める + 局所地図の照合 |

- 「疑い」の照合は止めずに走りながら行う。確かめれば正常に戻り、別の姿勢に決まれば置き直し、決まらなければ決めきれない。
- 今の実装は、状態ごとの固定の対処 (切り離し・一時停止・置き直し) で、程度と表はない。

### 対処の一覧

| 対処 | 中身 | 状況 |
| :--- | :--- | :--- |
| 記録 | イベントと診断 | 実装済み |
| 門を閉じる | 推定器を融合に渡さず、照合を求める | 実装済み |
| 減速 | 速度の上限を出す。出し手が複数なら小さい方 | 未実装 |
| 一時停止 | 走行側に止めてほしいと出す (出力の部品はロボット側) | 実装済み (監督の対処 1 つ) |
| 観測を増やす動作 | 首振りなど。中身はロボット側の対処が決める | 実装済み (監督の指示 `observe`) |
| 縮退走行 | 低速と、走ってよい距離の上限 | 未実装 |

## 復旧の段 (一部)

軽い順に試す。各段の停止の時間に上限を置き、超えたら次の段へ進む (不変条件 3)。

| 段 | 中身 | 状況 |
| :--- | :--- | :--- |
| 今の観測での照合 | 今の観測 (直近のスキャンの重ね) で候補を照合する | 実装済み (門の照合) |
| 局所地図の照合 | 窓のデータで長い局所地図を作り、予測の周りで地図と照合する | 一部 (監督の `submap_match` は直近の一定距離だけ) |
| 広い照合 | 局所地図を広い範囲で照合し、候補ごとに窓の軌跡の全体を説明できるかで選ぶ | 未実装 |
| 観測を増やしてやり直す | 観測を増やす動作をして、局所地図の照合からやり直す。回数の上限で縮退走行へ | 一部 (首振りと撒き直しの制限) |

- 決まる条件: 一致率が下限以上で、離れた次点との差が十分あり、すべての向きで拘束されていること。
- 置き直した後は、照合で確かめてから門を開ける。
- 重い段 (局所地図・広い照合) は低い優先度で動かす。

### 戻し方 (実装済み)

補正が小さければその場で置き直し、大きければ一時停止を求め、止まってから置き直す ([motion_gate.md](./motion_gate.md#戻し方))。止める時間に上限を置く。

## 確かめの要求 (未実装)

走行側 (例: 経路の計画の失敗、ロボットの形が地図の通れないセルにかかる) から、状態に依らず監督に照合を 1 回求め、結果を返す仕組み。

| 照合の結果 | 監督 | 走行側 |
| :--- | :--- | :--- |
| 確かめられた | 「確かめた」を出す | 脱出してよい |
| 別の姿勢に決まった | 置き直す | 計画し直す |
| 決まらない | 決めきれない × 重いとして、止めて段を進める | 一時停止し、後退・首振りをしない |

- 塞ぐ穴: 判定が遅れてずれた姿勢で脱出する、走行側が任せたのに監督が何もしない、監督の復旧と走行側の後退・首振りが同時に動く。
- 要求の頻度に上限を置く。

## 未初期化の処理 (起動・地図の切り替え) (実装済み)

起動の直後と地図の切り替えの後の姿勢は、監督の中の 1 か所で決める。

- 候補: 推定器、融合の結果、GNSS、GNSS の周りを向きの全周で照合した姿勢、外から与えた初期姿勢。どれも同じ照合の規則で比べる。
- 推定器と同じ仮説に決まれば置き直さない (収束の途中を邪魔しない)。別の仮説に決まったときだけ置き直す。
- 一致率が下限をわずかに超えるだけの決め方は通さない。今は、推定器と別の仮説に置き直すのを、全周の照合と同じ仮説に決まったときだけにしている (仮。[未確定の項目](#未確定の項目))。全周の照合が合わず、まだ一度も確かめていなければ、GNSS の位置を広い共分散で 1 回だけ出す ([motion_gate.md](./motion_gate.md#未初期化の処理-全周の照合があるとき))。
- 確かめるまでは動きの合意を使わない (収束の途中のため)。
- 全周の照合は、ロボット側の初期化の部品から枠組みの部品 (`core/initial_search.py`) に移した。統合の前 (門のノードの構成) は、門の起動の直後の確かめ (全周の照合なし) と、ロボット側の初期化の部品が別々に置き直しを出していた。根拠: 離れた所からの起動で、門が低い一致率で誤った姿勢を決め、初期化の部品の正しい姿勢を上書きした (2026-11-25 の Gazebo の計測。[localization_target.md](../../mg_navigation/doc/localization_target.md#根拠))。

### 手動の初期姿勢 (実装済み)

人が専用のトピックで与えた姿勢は、自動の置き直しとは別の経路として残す ([motion_gate.md](./motion_gate.md#手動の初期姿勢))。門があるときは、監督のノードが受ける。

## センサの組 (未実装)

センサの欠け (起動し直しても戻らない) から、今の組 (例: 全部 / LiDAR なし / カメラなし) を決める。

- 組ごとのプロファイルで決めるもの: 推定器に入れる情報源、対応表の升目の差し替え、許す動き (後退・首振り)、速さの上限。
- 判定は組に依らず同じ。欠けた情報源は「判定できない」。
- 組の決め方 (センサの途絶の見張りからの引き継ぎ) と、組ごとの走り方はロボット側に書く。

## 例外 (未実装)

不変条件を満たせない状況を、名前をつけて 1 つのファイルに持つ。適用する部品はこのパッケージに置き、一覧はロボット側のファイルを正とする。

- 項目ごとに書くもの: 名前、入る条件、緩める不変条件の番号、代わりの対処、出る条件、理由、試すシナリオ。
- 入る・出るときにイベント (`localization.exception_enter`・`localization.exception_exit`) を出し、診断と状態のメッセージに名前を出す。
- 抜け道にしない守り:
  - 不変条件の自動判定は、例外の間だけ、指定した条件を外す。
  - 例外を想定していないシナリオで例外に入ったら、不合格。
  - 例外の時間・距離をシナリオごとの上限として測る。
  - 例外ごとに、入らないことを確かめる対照のシナリオを置く。
  - 単体テストで、例外とシナリオの対応を確かめる。

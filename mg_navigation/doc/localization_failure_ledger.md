# 自己位置推定の失敗の台帳と完了基準

実機で起きた失敗と、再生・Gazebo で評価に使う事象を並べ、ロバスト化の完了をどう測るかを書く。経緯と判断は [localization_robustness.md](./localization_robustness.md)。閾値はシナリオの yaml を正とし、ここには書かない。数値は集計の時点の例。

## 実機の失敗

出どころの記録は 2026-09-13 の走行 (`~/ros2_data/rosbag/TC2026/20260913/`)。これらは地図作りと評価用のセンサの記録で、自律走行ではない。

| 事象 | 場所と記録 | 種類 | 再生での再現 |
| :--- | :--- | :--- | :--- |
| 角の回りすぎ | Region1 の角 (051635) | 峰は 1 つのまま、向きが十数秒かけて回りすぎる | `alpha` が今の値なら毎回。`robust` では出ない |
| 発進時の割れ | Region3 の前半 (051635) | 止まった後の発進で粒子が割れ、正しい峰が少数側になる | `alpha` が今の値なら毎回に近い。`robust` では出ない |
| 記録の途切れの後のずれ | Region3 の後半 (051635) | 全トピックが数秒途切れた直後の更新で、AMCL が誤った位置へ移る | `robust` でも出る |
| 地図と GNSS の局所的なずれ | Region4 (043837) | 地図と真値が例: 2.5 m ずれ、正しい GNSS が棄却される | 区間によって出る |

**記録にないこと。** 実機の自律走行で自己位置がずれた回数、止まった時間、人が介入した回数は、残っている記録からは分からない。自律走行の記録は `rosbag2_2026_09_13-07_01_28` (例: 105 秒) だけで、ここでは自己位置のずれは見えない (非常停止と後方の衝突判定で止まり、ゴールには着いている)。これらは現場の記憶か、今後の実機の記録で埋める。

## 想定する異常パターン

ロバスト化で考慮する異常を、環境・原因・結果の組で並べる。実機の失敗に加えて、2D LiDAR と GNSS を中心にした自己位置推定が一般に苦手とする場面を含む。対策と評価のシナリオは、この表の番号に対応づける。

前提: センサは追加しない。RealSense の IMU は自己位置推定にも監督にも使わない。処理の停止 (全トピックの途切れ) は記録時の負荷によるものとして、対象にしない。

| # | 環境 | 原因 | どうなる |
| :--- | :--- | :--- | :--- |
| 1 | 直交する線でできた角 | 旋回中に AMCL の向きが回りすぎる | 峰が 1 つのまま、自信を持ってずれた位置で走る |
| 2 | 停止の後の発進 | 粒子が割れ、誤った峰が勝つ | 位置が跳ぶ |
| 3 | 植栽・駐輪・時間がたった場所 | 測位用の地図と現場の形が食い違う | 誤った形に合い、戻らない |
| 4 | 広場・長い通路 | 進行方向の位置を決める特徴がない | ゆっくりずれる |
| 5 | 人混み | スキャンの大半が動く物に当たる | AMCL が弱る、または誤る |
| 6 | 傾斜・段差 | 2D のスキャンが地面や遠方を拾う | 地図にない壁に合う |
| 7 | 建物の横 | GNSS が、良い精度を申告したまま誤った座標を出す | GNSS での再初期化と重なると、誤った位置に撒かれる。推定位置が地図の障害物に重なり、経路を作れなくなる |
| 8 | 屋根の出入り | GNSS の精度が急に変わる (申告も悪くなる) | GNSS が効かなくなり、再初期化の拠り所を失う |
| 9 | 全域、または一部の区間 | 緯度経度から地図座標への変換がずれている (平行移動、回転) | 起動時にずれた位置へ撒かれる。走行中は正しい GNSS が棄却され続ける |
| 10 | 屋内・高架下 | GNSS の欠測 | GNSS での再初期化ができない |
| 11 | 濡れた路面・段差 | 車輪の滑り | オドメトリが跳び、AMCL が追えない |
| 12 | 場所を問わない | 止まっている間に異常が起きる、または異常で止まる | AMCL も GNSS も更新されず、止まったままになる |
| 13 | 障害物の近く | 推定位置が地図の障害物に重なる (3・7・9 の結果) | 経路を作れず、止まったままになる |
| 14 | 似た形が並ぶ場所、特徴の少ない場所 | 復旧の候補を選べない | 知らせるだけで、止まったままになる |
| 15 | 起動時・地図の切り替えの直後 | 初期姿勢が GNSS だけで決まり、向きは移動から求める | 向きの誤りを抱えて走り出す |

### 今の構成での扱い

watchdog の構成は、AMCL の共分散が大きいときに GNSS で再初期化する。監督の構成は [mg_localization_supervisor](../../mg_localization_supervisor/README.md)。
「確かめ方」は監督の構成の列についてのもの。watchdog の構成の列は、すべて実装を読んだ見立てで、試していない。

| # | watchdog の構成 | 監督の構成 (プリセット `robust` と組) | 確かめ方 |
| :--- | :--- | :--- | :--- |
| 1 | 共分散が小さいままなので気づけない | ずれない | 再生で確認 |
| 2 | 共分散が増えれば GNSS で戻す | 出ない | 再生で確認 |
| 3 | 気づけない | GNSS との食い違いで気づく。スキャンの判定は同じ地図を使うので弱い | 再生で 1 事象だけ確認 |
| 4 | 共分散が増えれば GNSS で戻す | 局所地図の照合が効かず、AMCL と GNSS のどちらが悪いかを決められない | 未検証 |
| 5・6 | 気づけない、または 4 と同じ | 同上 | 未検証 |
| 7 | 申告の精度だけで再初期化するので防げない | AMCL が正しいと示せれば GNSS だけを切り離す。示せないと止まり、誤った GNSS が候補になる | 未検証 |
| 8 | 再初期化できない | GNSS の候補がなくなる | 未検証 |
| 9 | 再初期化のたびにずれる | GNSS を切り離して走れる。復旧の候補から GNSS がなくなる | 未検証 |
| 10 | 戻せない | 推測航法とスキャンの照合で戻す | Gazebo で確認 |
| 11 | 未検証 | `alpha` が小さいので不利。AMCL の跳びの判定が、AMCL を誤って疑うおそれ | 未検証 |
| 12 | 戻せない | 止まっていると標本が古くなり、復旧の候補を作れない | Gazebo で確認 (既知の限界) |
| 13 | 脱出の動作は、位置が誤っていると意味がない | 疑っている間は復旧に任せる。復旧できなければ止まったまま | 未検証 |
| 14 | (復旧の候補を選ぶ仕組みがない) | `DEGRADED` で知らせて再試行するだけ | 再生で確認 (既知の限界) |
| 15 | そのまま走り出す | 起動の猶予の間は判定しない | 未検証 |

まとめると、扱えていないのは次の 4 つ。

- **復旧できないときの最終動作がない** (12・13・14)。
- **GNSS を検証せずに拠り所にしている** (7・9・15)。
- **AMCL と GNSS のどちらが悪いかを決められない場面が広い** (4・5・6・11)。
- **走行側が、止めるか通すかの二択** (疑いの段階で減速しない)。

## 評価に使う記録

| 記録 | 長さの例 | 使い道 |
| :--- | :--- | :--- |
| 051635 の Region1・Region3 | 数百秒 | 調整用。ずれの事象の主な出どころ |
| 043837 の Region4・Region5 | 数百秒 | 調整用 |
| 043837 の Region1〜3、051635 の Region2 | 数百秒 | 回帰用。どの構成でもずれがほぼ出ないので、誤停止と悪化の確認に使う |
| 041743 の Region5 | 例: 1000 秒 | 回帰用 (同上) |
| 055357 | 例: 8 秒 | 短すぎて使えない |

過去の再生で事象が出た区間は、すでに設定の調整に使っている。**事象を含む検証用の区間は今のところない。** 調整に使っていない事象は、手順 2 の弱らせた条件か、今後の実機の記録で作る。

### 区間の終わりで切れる事象

`map20261017r3_eval051635_win1242` の事象は、評価の終わりの例: 7〜8 秒前に始まる。「ずれたまま終わった」は、戻れなかったことを意味せず、戻るかどうかを見る時間がない。元の区間 `map20261017r3_eval051635` も同じ時刻で終わるので、この事象の「ずれたまま終わった」の数の増減を改善や悪化の根拠にしない。

## 完了基準

ゴールは、**角が複数ある経路を、人の操作なしで走りきること**。人手の介入は認めない。ずれそのものは失敗とせず、ずれたときの振る舞いで測る。経路の長さは warehouse の 1 周のウェイポイントを基準にする。

| 基準 | 定義 | 測る場所 |
| :--- | :--- | :--- |
| 走りきり | 全ゴールに、人の操作なしで着く | Gazebo の `reached_all` |
| 見逃し走行 | ずれているのに、止める要求なしで走った距離 | `localization_outcome` |
| 見かけの食い込み | 推定の footprint が事前地図の障害物にかかり、真の footprint はかかっていない状態の回数・長さ・解消 | `map_overlap` |
| 止まったまま | ゴールが有効な間に止まり続けた時間の最大 | `max_stop_duration` |
| 誤停止 | ずれていないのに止める要求を出した時間 (弱い条件でずれなかった試行を含む) | `localization_outcome`、再生の `hold` |
| 試験の成立 | ずれや見かけの食い込みが実際に起きたこと。起きない試行は ERROR | `require_deviation`、`require_overlap` |

- 上限の値は暫定で、シナリオの yaml を正とする。弱い条件の実測を見て決め直す。
- 構成の比較は 1 本の線の合否でなく、基準の構成との対応のある比較と、弱い条件の強さを変えた応答で見る。
- 角でのずれは必ず含める (`localization_corner_drift`、`localization_corner_odom`、`localization_corner_weak`)。見かけの食い込みは `localization_map_shift` で作る。
- 再生は開ループなので、見逃し (止める要求とずれの関係)、ずれた時間、誤停止を見る。監督がどの情報源を疑ったか (`blame`) は診断の記録で、合否に使わない。

## NEES の読み方

`eval_localization.py` は NEES を次の 2 通りで出す。

- **そのままの NEES:** 真値は地図と局所的にずれるので、共分散の正しさではなく、主にこの偏りを測っている。
- **偏りを除いた NEES (`residual`):** 誤差の移動中央値 (窓幅 `--nees-offset-window`、ずれの事象は除く) を偏りとして引く。ゆっくりしたずれも一緒に引かれ、誤差は時間に強く相関するので、値は小さく出る。

例: `robust` に監督を組んだ 7 条件で、そのままの中央値は 15〜152、偏りを除くと事象の外で 0.2〜0.6 (理想は約 2.4)。真の一貫性はこの間にあり、どちらも絶対値としては使えない。同じ区間の構成どうしの比較に使う。

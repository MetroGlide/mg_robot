# PLATEAU の建物を基準にして、地図と GNSS のずれを測る

## 背景

運用の地図は、GNSS つきの SLAM 地図を waypoint-tool のグループに分け、グループごとに手でずらして作る。ずらし量は、走行のスキャンを地図に照合して、RTK の測位を基準にした位置とのずれから決める ([gnss_transform_tools.md](../../tools/doc/gnss_transform_tools.md#measure_gnss_map_offsetpy-地図と-gnss-の場所ごとのずれ))。

この方法は、基準の質で精度が決まる。

- RTK Fix の区間は、走行の一部にしかない。RTK のない区間の基準は、SLAM の形で前後の RTK からつないだ位置 (外挿) で、RTK から離れるほど誤差が乗る。
- 区画によっては、どの走行にも RTK Fix の区間がない。そこでは、Float の測位との一致で確かめるか、決めきれずに実機で取り直すことになる。
- 衛星写真と目で重ねる方法は、写真の位置の誤差・建物の倒れ込み・目視の誤差が入る。

## 構想

国土交通省の 3D 都市モデル PLATEAU の建物の形を、壁の位置の基準に使う。走行の記録や RTK に依らず、建物のある所なら全域を一度に見られる。

- PLATEAU の建物 (LOD1・LOD2) の足元の輪郭を取り出し、経緯度 → UTM → `gnss_transform.yaml` で地図の座標に直す。
- 輪郭を占有格子にし、運用の地図の壁と、区画やグループごとに照合して、(x, y, 向き) のずれを出す。照合は `tools/common/map_align.py` の `match_cloud` を使える (輪郭を点群にして、運用の地図に照合する)。
- 出たずれは、今の流れと同じに、グループの剛体に当てはめて「直す動き」にし、`move_wptroj_groups.py` でプロジェクトに当てる。

使い方の候補:

| 使い方 | 長所 | 短所 |
| :--- | :--- | :--- |
| RTK のない区画の基準にする | 走行を取り直さずに、全区画を同じ基準で見られる | PLATEAU の精度がそのまま結果の精度になる |
| RTK の基準の確かめに使う | 計測の結果に、独立した確かめが加わる | 新しく直せる範囲は増えない |
| 地図を作るときに、SLAM の拘束に加える | 地図の形そのものが正しくなる | SLAM の変更が要り、手間が大きい |

## 入る場所

- 計測の道具 [measure_gnss_map_offset.py](../../tools/scripts/measure_gnss_map_offset.py) に、走行の代わりに PLATEAU の輪郭を照合する入力を足す。analyze の当てはめ・報告はそのまま使える。
- オフラインの道具だけで、実機で動くノードには触れない。実機の負荷は変わらない。
- PLATEAU のデータは大きく、ライセンスと出どころを明記して扱う。リポジトリには入れず、取得の手順だけを書く。

## 着手の前に確かめること

- **対象の範囲が整備されているか**、整備の年 (建て替えなどの反映) と LOD の種類。
- **PLATEAU の位置の精度**。整備の元の地図や航空写真の精度は、公共測量の規程の範囲で、今ほしい精度 (例: 数十 cm) を保証しない。RTK の基準がある区画で、PLATEAU の輪郭と RTK で求めた壁の位置を比べ、偏りとばらつきを測る。ここで足りなければ、使う範囲を絞るか見送る。
- **屋根と壁の差**。輪郭が屋根の縁のときは、LiDAR が見る壁の足元と、軒の出の分ずれる。建物の種類ごとに、上の比較で偏りが出るかを見る。
- **照合の手がかり**。塀・柵・植え込み・柱は入っていない。建物の少ない区間 (公園など) は、照合が決まらない。区画ごとに、輪郭のある壁の量を数える。

## やらないこと

- 画像生成で地図を描き直す: 壁の正しい位置の手がかりは増えず、根拠のない壁を地図に入れることになる。自己位置推定はその壁を信じるので、見た目で気付けない誤りになる。
- PLATEAU の輪郭で、運用の地図の壁を置き換える: 塀・柵などが消え、屋根と壁の差も入る。基準として使い、地図はスキャンで作ったものを使う。

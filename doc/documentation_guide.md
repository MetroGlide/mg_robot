# ドキュメントの書き方

このリポジトリの文書の置き場所、種類、書いてよいこと・書かないことの規約。文書を新設・変更するときに従う。

## 文書の種類

| 種類 | 役割 | 置き場所 |
| :--- | :--- | :--- |
| 入口 | 何のパッケージか、何があるか、最初に何をするか | パッケージルートの `README.md` |
| 使い方・運用 | 手順、トラブル時の見方、調整の進め方 | `doc/<主題>.md` |
| 解説 | 設計、責務の分担、判断の根拠 | `doc/architecture.md`、`doc/<主題>.md` |
| リファレンス | トピック・サービス・パラメータの意味、単位、値同士の関係 | `doc/interfaces.md`、`doc/parameters.md` |
| 構想 | 着手していない拡張のアイデア、前提、今の構成のどこに入るか、着手の前に確かめること | リポジトリの `doc/ideas/<主題>.md` |

1 つの文書に複数の種類を混ぜない。混ざってきたら主題で分ける。

## 構想

実装の前のアイデアは、パッケージの文書に混ぜず、`doc/ideas/` に 1 主題 1 ファイルで置く (書き方と一覧は [ideas/README.md](./ideas/README.md))。

- 構想には、実装済みの内容や今の動作の説明を書かない。今の動作は、各パッケージの文書へのリンクで示す。
- 着手したら、設計を正式な文書 (`architecture.md` など) に移し、構想の文書は削除する。見送ったものは、理由を残す。
- 関係するパッケージの文書からは、「将来の拡張」としてリンクだけ張る。内容は書き写さない (1 つの事実は 1 か所)。

## 値を書かない

設定値と既定値は、yaml・launch・`.env.example` だけが正とする。文書に書くと実装と食い違い、直す手間だけが残る。

- 書く: 意味、単位、取りうる範囲、値同士の関係、調整の考え方、根拠。
- 書かない: パラメータの現在値、launch 引数・環境変数の既定値、それらを並べた表の値の列。
- 数値を出す必要があるときは、「例:」と明記し、実際の値は yaml が正だと分かる書き方にする。
- 残してよいもの (運用上の取り決め): ポート番号、ファイルやディレクトリのパス、コマンド、環境変数・トピック・ノードの名前。判定基準は「変更しても動作の意味が変わらず、別の場所と食い違うと運用が壊れるもの」。迷うときは外す。
- 例外: 外部の実装者が読む形式・インターフェースのリファレンス (ウェイポイントやシナリオのファイル形式、BT ノードのポート) は、省略したときの既定値を書く。利用者が値を省略して書くので、既定値が仕様の一部になるため。ファイルの形式を変えたら、既定値も同時に直す。
- 値同士の関係は文書でなくテストで守る (見本: `mg_navigation/test/test_nav2_params_consistency.py`)。

## 1 つの事実は 1 か所

同じ内容を複数の文書に書かず、1 か所に書いてリンクする。パッケージの一覧、速度指令の経路、監視の規約などが対象。

## パッケージの文書

- `README.md` (必須): 概要、構成要素 (ノード・launch の名前と役割だけ)、クイックスタート、依存 (`package.xml` へリンク)、テスト、ドキュメントの目次。
- `doc/` は、README が長くなる、または設計を語るパッケージだけに作る。ディレクトリ名は `doc/` に統一する。
- 文書名: `architecture.md` (構成・責務・データの流れ)、`interfaces.md`、`parameters.md`、`<主題>.md` (運用手順・調整の考え方)。
- README の行数は、超えたら分割を検討する目安 (100〜150 行)。分割の基準は、主題が複数あるかどうか。
- 小さいパッケージは README だけでよい。`mg_ui` はサブパッケージごとに `doc/` を持てる。
- パッケージ内に `AGENTS.md` を新設しない。開発ルールは README か `doc/` に書く。
- `nav2_pkg` と `geometry2_pkg` は上流の取り込みなので、文書も変更しない (他の文書からのリンク先が変わるときの追従を除く)。

## 寿命

- パッケージの `doc/` に置くのは恒久の文書だけ。作業メモは完了後に削除する (移行中の `mg_ui/mg_web_ui/doc/ui_migration_todo.md` が例外)。構想は、リポジトリの `doc/ideas/` に置き、着手したら削除する。
- 生成物は `tools/data/` など Git 追跡外に置く。

## 検査

- 文書内の相対リンクとアンカー、コードや設定から `doc/*.md` を指す参照は、pytest (`tools/test/test_docs_links.py`) で実在を検査する。
- 文書を移動・改名したら、検査が通ることを確かめる。
